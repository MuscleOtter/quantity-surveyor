The standard-library implementation is in [QS16.py](QS16.py). It returns a new object without modifying the inputs, writing files or making network calls. Codes and allowed units come solely from the supplied B01/B02/B03 framework. Quantities and rates must be finite nonnegative real numbers; booleans are rejected. Unknown codes and unit mismatches raise `ValueError` rather than being recoded.

Illustrative call (the supplied rows are also included in the file):

```python
from QS16 import normalize_costs

result = normalize_costs([
    {"id": "r1", "code": "B01", "qty": 30, "unit": "m3", "rate_USD": 110},
    {"id": "r2", "code": "B02", "qty": 250, "unit": "m2", "rate_USD": 420},
    {"id": "r3", "code": "B03", "qty": 80, "unit": "m", "rate_USD": 250},
])
```

Reconciliation: 30 × 110 + 250 × 420 + 80 × 250 = 3,300 + 105,000 + 20,000 = **USD 128,300**. No additions or code substitutions are made. The function uses numeric floats without rounding each row; totals use `math.fsum`.

Actual synthetic validation rejected all six requested mutations with `ValueError`: duplicate r1; B99; quantity −1; B01 unit kg; NaN rate; and boolean quantity. Additional executed checks covered negative rate, infinite quantity, boolean rate, zero quantity, empty input retaining all three zero element totals, and unchanged source rows. Results are recorded in [tester-b-calculations.json](../tester-b-calculations.json). No project memory was used or persisted by the function.
