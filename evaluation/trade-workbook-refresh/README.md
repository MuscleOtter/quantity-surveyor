# Trade and workbook transfer — pending 2.1.0

This candidate ports original, reusable drawing and trade procedures into the portable public skill, alongside an optional blank estimating workbook. It does not distribute the local private company configuration, proprietary sources, source-search database, private memory or company lookup helper. Company/Unifier wording explicitly requires user-supplied definitions and version evidence.

## Frozen relationship to earlier evidence

`baseline-2.0.3/` and `baseline-hashes.json` preserve the prior public package. `changes.json` records the exact core/version substitutions; `added-files.json` lists the eight new distributable files. `candidate-hashes.json` freezes the complete new canonical package. Existing historical answers, cases, grades and hash manifests were not edited. Validation checks the old chain and this explicit additive delta; historical scores do not transfer to the new references or workbook.

`fixtures/request.txt`, `fixtures/transfer-cases.pdf`, `expected.json` and `candidate-hashes.json` were frozen in `frozen.json` before independent evaluator dispatch. The evaluator received only the raw request/PDF and candidate instructions, without the expected answers, baseline or earlier evaluations. A separate critic receives the raw fixtures, frozen key and actual outputs, without the candidate or previous critiques. Actual outputs are in `run/`; critic findings are in `critic/`. All three fresh cases passed the independent mandatory checks, with tolerance declaration timing retained as a self-reported process limit. `response-hashes.json` preserves the published outputs and workbook checks. `publication-changes.json` records link-only corrections and original hashes when synthetic calculation files were copied out of ignored temporary directories; numerical answers and grades are unchanged.

These new cases test a dimensioned wall with material-only waste and a height revision, rejection of distorted graphical calibration, and repeated stone-floor descriptions with owner supply and included bedding. They do not exercise every new trade prompt, a coordinated real project, company configuration or live workbook edits. One run without a baseline arm cannot establish causal skill lift, human equivalence, general accuracy or NRM conformity. The published fixtures become regression cases, not future held-out evidence.

## Workbook and deterministic verification

The workbook was authored with the bundled spreadsheet authoring tool and visually inspected across all seven sheets. `workbook-checks.json` records 30 executed input-state checks, including missing inputs, explicit zero values/allocations, duplicate IDs, units/currency, supported versus scenario prices, coding residuals and revision reconciliation. An explicit zero-price allocation defect was corrected before this asset was frozen. The results are historical evidence of that authoring run, not a portable recalculation engine or a test of every spreadsheet application.

The public validator checks the exported file's ZIP structure, seven visible sheets, external-link/macro absence, cached errors, private host-path absence, candidate hash and exact distribution bytes. Those structural checks do not recalculate formulas. Use the user's spreadsheet capability to verify actual project inputs and the 100-row capacity described in `workbook-pattern.md`.

Executed repository checks: package validation/build, all ten update tests, all 13 memory-helper subprocess cases, and missing-primary recovery/preservation regression. Helper implementations are unchanged. Gitleaks reported no leaks in the canonical distributable; that is a bounded secret scan, not a security certification.

Source version 2.1.0 is pending review/release. The Git branch/PR does not publish a GitHub release, change existing stable downloads or update anyone's installed skill.

## Clean-checkout packaging correction

The first GitHub checks failed because the initial candidate/baseline hash manifests included temporary interpreter caches excluded by Git. `baseline-hashes-with-caches.json` and `candidate-hashes-with-caches.json` preserve those original manifests; `frozen.json` still records the original dispatch freeze. The portable manifests remove only `__pycache__`, `.pyc` and `.pyo` entries. Validation verifies the archived initial freeze, exact non-cache subset and every shipped source byte. Fixtures, expected answers, candidate instructions, actual responses and grades are unchanged. Clean-checkout validation and CI are rerun rather than relying on locally available caches.
