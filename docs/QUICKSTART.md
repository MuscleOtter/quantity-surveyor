# Choose your first task

Start with one deliverable, a clear scope and the relevant issued inputs. The AI should perform supported work and ask focused questions for material gaps. The [feature guide](FEATURES.md) describes each workflow in detail.

## Review a drawing set

> Use Quantity Surveyor to review this issued set for a door take-off. Compare the drawing index with the actual files, establish the applicable revisions and locate the plans, schedules and details. Report missing references, then review a representative batch with evidence for each count. Keep inspected coverage and unresolved scope separate.

Attach the drawing index/transmittal, drawings and relevant specifications. Expect a drawing register, supported partial quantities and a prioritized query list. The host needs visual access for drawing inspection.

## Measure quantities

> Prepare a concrete take-off from the attached plans and sections. Separate slabs, beams and foundations by location. Show dimensions, thicknesses, counts, deductions and volume calculations in m³, with a source revision/location for each line. Keep measured quantities separate from any supplied procurement waste. List missing dimensions rather than guessing.

Attach readable drawings or explicit dimensions and the applicable measurement convention. Expect a quantity schedule; rates are optional for this task.

## Build an estimate and unit rates

> Build an itemized estimate from these quantities and quotes. Show quantity × rate, rate inclusions, currency and price date. For unquoted items, use only the labour/material/equipment inputs I supply. Show waste, productivity and each addition's base. Reconcile the total and keep unpriced scope visible.

Attach quantities, quotes/rate inputs, tax basis and known inclusions. Expect an estimate, rate build-ups and a pricing query list.

## Check whole-project scope

> Review this cost plan against the project brief and package scopes. Check enabling works, structure, envelope, finishes, services, utilities/site works, temporary works, commissioning and owner costs as relevant. Show who carries each item, where it is included and what remains excluded or unpriced. Allocate shared costs only once.

Attach the brief, cost plan, package boundaries and programme. Expect a coverage matrix and interface questions. The [project basis template](../skills/quantity-surveyor/templates/project-basis.md) can help organize the inputs.

## Compare tenders

> Compare these three building-services bids on the same scope. Preserve submitted totals, show evidence for each adjustment and separate contractor-confirmed changes from scenario allowances. List exclusions, qualifications and unpriced exposures. Give a conditional recommendation based on compliance and cost.

Attach bids, scope requirements, qualifications, commercial terms and programme constraints. Expect an adjusted comparison and targeted clarifications.

## Reconcile forecast and changes

> Reconcile these budget, purchase-order, amendment, payment and change records as of the supplied cut-off date. Identify revised-total versus incremental amendments. Count paid amounts within full commitments only once. Show forecast final cost, variance to approved budget, movement from the previous forecast and each pending change's inclusion point.

Attach dated ledgers with unique IDs and definitions. Expect a forecast reconciliation and change log. A code match is not proof of financial inclusion.

## Plan cash flow

> Build an owner payment forecast from this programme and contract payment schedule. Apply the supplied deposit/recovery terms, payment lag, retention cap and release dates. Show period cash, cumulative cash and outstanding retention/advances. Reconcile the final total and disclose liabilities after the reporting horizon.

Attach work values/milestones, programme and payment terms. Expect a payment schedule with balance checks.

## Compare value-engineering options

> Compare the baseline and proposed option at equivalent installed scope. Include purchase, installation, redesign, testing, access, logistics, programme and consequential works where supported. Show net savings, unresolved costs and approval dependencies. Check mandatory performance requirements before recommending an option.

Attach option specifications, prices and constraints. Expect an option comparison with conditional savings and decisions required.

## Compare maintenance and lifecycle costs

> Compare these two systems over the supplied study period and real discount rate. Use the supplied maintenance frequencies, replacement dates and residual values. Show event schedules, discounted subtotals and sensitivity to the uncertain service-life assumptions. Keep real/nominal and tax treatment consistent.

Attach asset quantities, event costs, service-life evidence and timing conventions. Expect a present-value comparison and sensitivities, not a guessed remaining-life assessment.

## Reconcile cost codes

> Map this estimate to the attached approved code definitions. Split mixed scope only where evidence supports it. Keep confirmed, provisional and unallocated amounts separate, retain credits and reconcile all categories to the original total. List the definitions needed to resolve remaining mappings.

Attach the code dictionary/version and any authorized crosswalk. Expect a coded schedule and unresolved mapping queries.

## What a useful answer should contain

Request units, reproducible workings, source/revision locators, stated rate and percentage bases, detail-to-total reconciliation, and assumptions/questions beside affected results. Unknown scope should stay visible. The [templates](FEATURES.md#templates-and-file-formats) provide optional starting columns; use your own format when appropriate.

Optional memory is off until you choose a private root and explicit user/project scope. It is not needed for these tasks. Keep project files and private memory outside the public repository.
